📖 Manual de Java INPRO

1.1 — Estructura de un programa Java

1.1.1 — El esqueleto mínimo

Todo programa Java arranca desde un método llamado main, que debe residir dentro de una class. El compilador busca esa firma exacta para comenzar la ejecución. Si falta o está mal escrita, el programa no corre.

public class MiPrograma {
    public static void main(String[] args) {
        System.out.println("¡Hola, Java!");
    }
}

1.1.2 — Significado de cada palabra clave

PalabraSignificado
publicModificador de acceso. Permite que la JVM vea la clase y el método desde cualquier parte.
classDefine un nuevo tipo (molde). Todo el código ejecutable vive dentro de clases.
staticEl método pertenece a la clase, no a una instancia. La JVM puede llamarlo sin crear objetos.
voidEl método no devuelve ningún valor.
mainNombre especial reservado. La JVM busca public static void main(String[]) como punto de entrada.
String[] argsParámetro que recibe argumentos de línea de comandos. String[] es un array de cadenas.
System.out.printlnImprime texto en consola y agrega un salto de línea al final.

1.1.3 — Punto y coma y llaves

Cada instrucción termina con ;. Olvidarlo produce un error de compilación. Las llaves { } delimitan bloques de código: cuerpo de la clase, cuerpo del método, cuerpo de estructuras de control.

1.1.4 — Comentarios

// Comentario de una línea: el compilador ignora todo hasta el final de la línea

/* Comentario de múltiples líneas:
   útil para documentar bloques largos
   o desactivar código temporalmente */

1.1.5 — Errores comunes

ErrorCausaSolución
Falta mainNombre mal escrito (Main, principal)Usar exactamente main en minúscula
Falta staticSe omitió la palabra claveAgregar static antes de void
Falta ;Olvido de punto y comaVerificar que cada sentencia termine con ;
Llaves desbalanceadasFalta una { o }Contar que cada apertura tenga su cierre

💡 Dato clave: El nombre del archivo debe coincidir exactamente con el nombre de la clase pública. Si la clase se llama MiPrograma, el archivo debe llamarse MiPrograma.java.

1.2 — Tipos de datos primitivos

1.2.1 — Los ocho primitivos

Java tiene ocho tipos de datos primitivos. No son objetos: almacenan el valor directamente en memoria, lo que los hace muy eficientes.

1.2.2 — Declaración de variables

Sintaxis universal: tipo nombre = valor;. Java es de tipado estático: una vez declarado el tipo no puede cambiar.

int edad = 20;                  // Entero

boolean esEstudiante = true;    // Booleano
char inicial = 'S';             // Carácter (comillas simples)

Los nombres de variables comienzan con minúscula y cada palabra subsecuente con mayúscula: nombreCompleto, cantidadProductos, esMayorDeEdad. Las clases comienzan con mayúscula: Persona, Calculadora.

1.2.4 — Constantes con final

La palabra clave final impide que una variable cambie de valor después de su inicialización. Por convención se escriben en MAYÚSCULAS_CON_GUION_BAJO.

final double PI = 3.1416;
final int MAX_INTENTOS = 3;
final String NOMBRE_APP = "Java INPRO";

1.3 — Operadores

1.3.1 — Operadores aritméticos

OperadorSignificadoEjemploResultado

-Resta10 - 46
*Multiplicación6 * 742
/División15 / 43 (¡entera!)
%Módulo (resto)15 % 43

1.3.2 — División entera

Cuando ambos operandos son enteros, Java realiza división entera: el resultado se trunca, no se redondea. 15 / 4 da 3, no 3.75. Para obtener decimales, al menos un operando debe ser double: 15.0 / 4 o (double) 15 / 4.

1.3.3 — Operadores de asignación compuesta

int x = 10;
x += 5;   // x = x + 5  → 15
x -= 3;   // x = x - 3  → 12
x *= 2;   // x = x * 2  → 24
x /= 4;   // x = x / 4  → 6
x %= 5;   // x = x % 5  → 1

1.3.4 — Incremento y decremento

Los operadores ++ y -- suman o restan 1 en una sola operación. Existen en dos variantes:

  • Prefijo (++x): incrementa primero, luego usa el valor.
  • Postfijo (x++): usa el valor actual, luego incrementa.
int a = 5;
int b = ++a;   // a=6, b=6 (prefijo)
int c = a++;   // c=6, a=7 (postfijo)

1.3.5 — Precedencia de operadores

De mayor a menor prioridad:

  1. Paréntesis ( )
  2. Incremento/decremento prefijo ++x --x
  3. Multiplicación, división, módulo * / %
  4. Suma y resta + -
  5. Asignación = += -= *= /= %=

Ante la duda, usar paréntesis: (a + b) * c es más claro que depender de la precedencia.

1.3.6 — Errores comunes

ErrorEjemploProblema

Confundir = con ==if (a = 5)Asigna en vez de comparar

1.4 — La clase String

1.4.1 — Creación de Strings

Los String en Java son objetos inmutables: una vez creados, su contenido no puede modificarse. Cada operación que "modifica" un String en realidad crea uno nuevo.

String s1 = "Hola";                     // Literal (pool de strings)
String s2 = new String("Hola");         // Constructor explícito (objeto nuevo)
String s3 = s1 + " Mundo";              // Concatenación: "Hola Mundo"

1.4.3 — equals() vs ==

Este es uno de los errores más frecuentes en Java:

  • == compara referencias (¿apuntan al mismo objeto en memoria?).
  • equals() compara el contenido (¿tienen los mismos caracteres?).
String a = new String("Hola");
String b = new String("Hola");
System.out.println(a == b);       // false (objetos distintos)
System.out.println(a.equals(b));  // true  (mismo contenido)

1.4.4 — Concatenación con +

El operador + concatena Strings. Si uno de los operandos no es String, Java lo convierte automáticamente llamando a toString() o a su representación textual.

String nombre = "Sonic";
int edad = 25;
String mensaje = "Hola, soy " + nombre + " y tengo " + edad + " años.";
// Resultado: "Hola, soy Sonic y tengo 25 años."

1.5 — Math y conversiones de tipos

1.5.1 — La clase Math

Math es una clase utilitaria con métodos estáticos. No se instancia; todos sus métodos se llaman directamente con Math..

MétodoDescripciónEjemplo

Math.sqrt(x)Raíz cuadradaMath.sqrt(16) → 4.0

1.5.2 — Casting explícito (estrechamiento)

Cuando se convierte de un tipo más grande a uno más pequeño, hay riesgo de pérdida de datos. Java exige un cast explícito:

double pi = 3.1416;
int entero = (int) pi;     // 3 (pierde los decimales)
long grande = 1000L;
int chico = (int) grande;  // OK si el valor cabe

1.5.3 — Casting implícito (ensanchamiento)

Java convierte automáticamente de un tipo más pequeño a uno más grande, porque no hay pérdida de información:

int a = 42;
double b = a;     // 42.0 — conversión implícita, sin cast
long c = a;       // 42L — también implícita

La jerarquía de ensanchamiento: byte → short → int → long → float → double. El char puede ensancharse a int.

1.5.4 — Parseo de Strings a números

Las clases wrapper proveen métodos para convertir cadenas en valores numéricos:

String texto = "42";
int numero = Integer.parseInt(texto);        // 42
double decimal = Double.parseDouble("3.14"); // 3.14
long largo = Long.parseLong("1000000");      // 1000000L
boolean flag = Boolean.parseBoolean("true"); // true

Si el String no es un número válido, parseInt lanza NumberFormatException.

1.5.5 — Conversión de números a String

int edad = 25;
String s1 = String.valueOf(edad);   // "25"
String s2 = Integer.toString(edad); // "25"
String s3 = "" + edad;              // "25" (truco de concatenación)
💡 Regla nemotécnica: Para convertir String → número usa Wrapper.parseTipo(). Para número → String usa String.valueOf() o simplemente concatena con "".

2.1 — Estructuras condicionales: if / else / else if

2.1.1 — if simple

Ejecuta un bloque de código únicamente si una condición booleana se evalúa como true.

int edad = 20;
if (edad >= 18) {
    System.out.println("Sos mayor de edad");
}

2.1.2 — if/else

Proporciona un camino alternativo cuando la condición es false.

double nota = 5.5;
if (nota >= 7.0) {
    System.out.println("Aprobado");
} else {
    System.out.println("Desaprobado");
}

2.1.3 — if/else if/else

Evalúa múltiples condiciones en secuencia. La primera que sea true se ejecuta; el resto se ignora.

double nota = 8.2;
if (nota >= 9.0) {
    System.out.println("Sobresaliente");
} else if (nota >= 7.0) {
    System.out.println("Notable");
} else if (nota >= 5.0) {
    System.out.println("Aprobado");
} else {
    System.out.println("Insuficiente");
}

2.1.4 — Operadores de comparación

OperadorSignificadoEjemplo

!=Distinto dea != b
>Mayor quea > b
<Menor quea < b
>=Mayor o iguala >= b
<=Menor o iguala <= b

2.1.5 — Operador ternario ?:

Es un if/else compacto que devuelve un valor. Sintaxis: condición ? valorSiVerdadero : valorSiFalso.

int edad = 20;
String estado = (edad >= 18) ? "Mayor" : "Menor";
System.out.println(estado);  // "Mayor"

2.2 — switch / case

2.2.1 — Estructura básica

Evalúa una variable y salta directamente al case que coincide. Es más legible que múltiples if/else if cuando se compara la misma variable contra muchos valores constantes.

int dia = 3;
switch (dia) {
    case 1: System.out.println("Lunes"); break;
    case 2: System.out.println("Martes"); break;
    case 3: System.out.println("Miércoles"); break;
    case 4: System.out.println("Jueves"); break;
    case 5: System.out.println("Viernes"); break;
    case 6: System.out.println("Sábado"); break;
    case 7: System.out.println("Domingo"); break;
    default: System.out.println("Día no válido");
}

2.2.2 — break y fall-through

Sin break, la ejecución "cae" al siguiente case (fall-through). Esto es útil para agrupar casos que comparten el mismo código:

switch (dia) {
    case 1: case 2: case 3: case 4: case 5:
        System.out.println("Día laboral");
        break;
    case 6: case 7:
        System.out.println("Fin de semana");
        break;
}

2.2.3 — Tipos permitidos

El switch acepta: byte, short, int, char, String (desde Java 7) y enum.

2.2.4 — switch vs if-else: cuándo usar cada uno

Criterioswitchif/else if
ComparaciónSolo igualdad exactaRangos, desigualdades, condiciones complejas
LegibilidadExcelente con muchos valores fijosMejor para pocas condiciones o rangos
RendimientoSalto directo (tableswitch/lookupswitch)Evalúa secuencialmente

2.2.5 — Errores comunes

ErrorConsecuencia
Olvidar breakSe ejecutan todos los cases siguientes (fall-through)
Olvidar defaultSi ningún case coincide, no se ejecuta nada
Case con rangocase > 10: no compila; los cases deben ser valores constantes
Cases duplicadosError de compilación: duplicate case label

2.3 — Operadores lógicos

2.3.1 — AND lógico (&&)

Devuelve true solo si ambas condiciones son true. Si la primera es false, la segunda no se evalúa (cortocircuito).

int edad = 25;
boolean tieneLicencia = true;
if (edad >= 18 && tieneLicencia) {
    System.out.println("Puede conducir");
}

2.3.2 — OR lógico (||)

Devuelve true si al menos una condición es true. Si la primera es true, la segunda no se evalúa (cortocircuito).

boolean esFinde = (dia == 6 || dia == 7);
if (esFinde || esFeriado) {
    System.out.println("No se trabaja");
}

2.3.3 — NOT lógico (!)

Invierte el valor booleano: true se vuelve false y viceversa.

boolean cerrado = false;
if (!cerrado) {
    System.out.println("El local está abierto");
}

2.3.4 — Tabla de verdad

ABA && BA || B!A
truetruetruetruefalse
truefalsefalsetruefalse
falsetruefalsetruetrue
falsefalsefalsefalsetrue

2.3.5 — Diferencia entre & / && y | / ||

  • & y | no hacen cortocircuito: evalúan ambos lados siempre.
  • && y || hacen cortocircuito: si el resultado ya está decidido, no evalúan el lado derecho.
  • El cortocircuito es útil para evitar errores: if (s != null && s.length() > 0) evita NullPointerException.

2.3.6 — Precedencia con operadores lógicos

  1. ! (NOT)
  2. && (AND)
  3. || (OR)

Usar paréntesis para claridad: if ((a > 5 && b > 5) || c > 10).

2.4 — Entrada de datos: Scanner

2.4.1 — Importación y creación

Scanner pertenece al paquete java.util. Debe importarse antes de usarse.

import java.util.Scanner;

public class Entrada {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Ingresá tu nombre: ");
        String nombre = sc.nextLine();
        System.out.println("Hola, " + nombre);
        sc.close();
    }
}

2.4.2 — Métodos principales de Scanner

2.4.3 — El bug del nextLine() después de nextInt()

Cuando se lee un entero con nextInt(), el carácter de salto de línea (\n) queda en el buffer. Si a continuación se llama a nextLine(), este consume ese salto de línea vacío en lugar de esperar una nueva entrada.

// ❌ Problema: el nextLine() no espera entrada
System.out.print("Edad: ");
int edad = sc.nextInt();
System.out.print("Nombre: ");
String nombre = sc.nextLine();  // Lee el \n residual

// ✅ Solución: consumir el salto de línea sobrante
System.out.print("Edad: ");
int edad = sc.nextInt();
sc.nextLine();                   // Limpia el buffer
System.out.print("Nombre: ");
String nombre = sc.nextLine();   // Ahora sí espera entrada
💡 Regla práctica: Después de cualquier nextInt(), nextDouble() o next(), si el siguiente input es un nextLine(), agregá un nextLine() extra para limpiar el buffer.

2.5 — Bucles: while y do-while

2.5.1 — while (condición primero)

Evalúa la condición antes de cada iteración. Si es false desde el inicio, el bloque no se ejecuta nunca.

int contador = 1;
while (contador <= 5) {
    System.out.println("Iteración: " + contador);
    contador++;   // Sin esto: bucle infinito
}

2.5.2 — do-while (al menos una vez)

Ejecuta el bloque primero y evalúa la condición después. Garantiza al menos una iteración.

int contador = 10;
do {
    System.out.println("Esto se imprime al menos una vez");
    contador++;
} while (contador <= 5);

2.5.3 — while vs do-while: cuándo usar cada uno

  • while: cuando la condición debe cumplirse para entrar al bucle (ej: leer un archivo mientras haya líneas).
  • do-while: cuando el bloque debe ejecutarse al menos una vez (ej: menú que se muestra antes de preguntar si continuar).

2.5.4 — Bucle infinito

Ocurre cuando la condición nunca se vuelve false. Es un error común cuando se olvida actualizar la variable de control.

// ❌ BUCLE INFINITO: falta i++
int i = 0;
while (i < 10) {
    System.out.println(i);
}
// ✅ Solución: agregar i++ dentro del bloque

2.5.5 — Errores comunes con while

ErrorConsecuencia
Olvidar actualizar la variable de controlBucle infinito
Punto y coma después del whilewhile (cond); { ... } — bucle vacío infinito
Condición que nunca es trueEl bloque nunca se ejecuta
Off-by-oneUna iteración de más o de menos por usar < en vez de <=

2.6 — Bucle for, break y continue

2.6.1 — for clásico

Compacta en una sola línea la inicialización, la condición y el paso. Ideal cuando se conoce de antemano la cantidad de iteraciones.

for (int i = 0; i < 5; i++) {
    System.out.println("Valor de i: " + i);
}
// Partes: (inicialización; condición; paso)

2.6.2 — break

Sale inmediatamente del bucle, sin evaluar la condición nuevamente.

for (int i = 1; i <= 10; i++) {
    if (i == 5) {
        break;   // Sale del bucle cuando i=5
    }
    System.out.println(i);  // Imprime 1,2,3,4
}

2.6.3 — continue

Salta a la siguiente iteración, ignorando el resto del bloque actual.

for (int i = 1; i <= 5; i++) {
    if (i == 3) {
        continue;  // Salta la iteración cuando i=3
    }
    System.out.println(i);  // Imprime 1,2,4,5
}

2.6.4 — For-each (enhanced for)

Recorre arrays y colecciones sin necesidad de un índice. Más limpio y menos propenso a errores de límites.

int[] numeros = {10, 20, 30, 40, 50};
for (int n : numeros) {
    System.out.println(n);
}
// Se lee: "para cada int n en el array numeros"

2.6.5 — Comparativa for vs while vs for-each

EstructuraMejor paraLimitación
forNúmero conocido de iteracionesMás verboso que for-each
whileCondición de salida desconocida (leer archivo, esperar evento)Requiere inicialización externa
do-whileAl menos una ejecución garantizadaPoco usado; verificar que realmente se necesita
for-eachRecorrer colecciones completasNo se puede modificar el array ni obtener el índice

2.7 — Arrays

2.7.1 — Declaración e inicialización

Un array es una estructura que almacena múltiples valores del mismo tipo en posiciones contiguas de memoria. Su tamaño es fijo una vez creado.

// Forma 1: declarar y luego inicializar
int[] notas = new int[5];  // Array de 5 enteros, todos en 0

// Forma 2: inicialización directa con valores
String[] dias = {"Lunes", "Martes", "Miércoles", "Jueves", "Viernes"};

// Forma 3: declarar, luego asignar
double[] precios;
precios = new double[]{10.5, 20.0, 15.75};

2.7.2 — Índices y acceso

Los índices comienzan en 0 y terminan en length - 1. Intentar acceder a un índice fuera de rango lanza ArrayIndexOutOfBoundsException.

int[] nums = {10, 20, 30, 40, 50};
System.out.println(nums[0]);       // 10 (primer elemento)
System.out.println(nums[4]);       // 50 (último elemento)
System.out.println(nums.length);   // 5 (atributo, no método: sin paréntesis)

nums[2] = 99;  // Modifica el tercer elemento
// nums[5] = 60;  // ❌ ArrayIndexOutOfBoundsException

2.7.3 — Recorrido de arrays

String[] frutas = {"Manzana", "Banana", "Naranja"};

// Recorrido con for clásico (tenés acceso al índice)
for (int i = 0; i < frutas.length; i++) {
    System.out.println("Posición " + i + ": " + frutas[i]);
}

// Recorrido con for-each (más limpio, sin índice)
for (String fruta : frutas) {
    System.out.println(fruta);
}

int[][] matriz = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};
System.out.println(matriz[1][2]);  // 6 (fila 1, columna 2)

2.8 — Paradigmas de programación: POP vs POO

2.8.1 — Programación Orientada a Procedimientos (POP)

El programa se organiza como una secuencia de instrucciones y funciones. Los datos y las funciones están separados. Se piensa en términos de "qué pasos hay que seguir". Lenguajes representativos: C, Pascal, Fortran.

2.8.2 — Programación Orientada a Objetos (POO)

El programa se organiza como un conjunto de objetos que interactúan entre sí. Cada objeto contiene datos (atributos) y comportamientos (métodos) encapsulados juntos. Se piensa en términos de "qué entidades participan y qué pueden hacer". Lenguajes representativos: Java, C++, Python, C#.

2.8.3 — Los 4 pilares de la POO

PilarDefiniciónEn Java
EncapsulamientoOcultar datos internos, exponer solo lo necesarioprivate + getters/setters
HerenciaCrear nuevas clases basadas en clases existentesextends
PolimorfismoUn mismo método se comporta distinto según el objeto@Override, upcasting
AbstracciónMostrar solo lo esencial, ocultar complejidad internaabstract class, interface
💡 Regla nemotécnica: Los 4 pilares forman el acrónimo E-H-P-A: Encapsulamiento, Herencia, Polimorfismo, Abstracción.

3.1 — Métodos

3.1.1 — ¿Qué es un método?

Un método es un bloque de código con nombre que realiza una tarea específica. Recibe datos de entrada (parámetros), los procesa y puede devolver un resultado. Es la unidad básica de organización del comportamiento en Java.

3.1.2 — Métodos void (sin retorno)

Realizan una acción pero no devuelven ningún valor. Se usan para imprimir, modificar atributos, enviar datos, etc.

public static void saludar(String nombre) {
    System.out.println("¡Hola, " + nombre + "!");
}

// Llamada
saludar("Sonic");  // Imprime: ¡Hola, Sonic!

3.1.3 — Métodos con retorno

Devuelven un valor al código que los llamó usando la palabra clave return. El tipo de retorno debe coincidir con lo declarado.

public static int sumar(int a, int b) {
    int resultado = a + b;
    return resultado;
}

public static boolean esMayorDeEdad(int edad) {
    return edad >= 18;  // Retorna true o false directamente
}

// Uso
int total = sumar(5, 3);        // 8
if (esMayorDeEdad(20)) { ... }  // true

3.1.4 — Parámetros y argumentos

  • Parámetro: variable declarada en la definición del método (int a en sumar(int a, int b)).
  • Argumento: valor real que se pasa al llamar al método (5 en sumar(5, 3)).
  • Java usa pass-by-value: el método recibe una copia del valor, no la variable original. Para objetos, se copia la referencia, no el objeto mismo.

3.1.5 — static: cuándo y por qué

static significa que el método pertenece a la clase, no a instancias individuales. Se llama con Clase.metodo() sin necesidad de crear un objeto.

  • Usar static para métodos utilitarios (Math.sqrt(), Integer.parseInt()).
  • No usar static cuando el método necesita acceder a atributos de instancia.
  • Un método static solo puede llamar a otros métodos static y acceder a variables static.

3.1.6 — Scope (alcance) de variables

Las variables declaradas dentro de un método solo existen dentro de ese método. Las variables declaradas dentro de un bloque { } solo existen dentro de ese bloque.

public static void ejemplo() {
    int x = 10;           // Scope: todo el método
    if (x > 5) {
        int y = 20;       // Scope: solo dentro del if
        System.out.println(x + y);  // OK, ambos visibles
    }
    // System.out.println(y);  // ❌ ERROR: y no existe aquí
}

return en método voidNo se puede devolver un valor en un método void
Llamar método no static desde staticCrear una instancia o hacer el método static

3.2 — Clases y Objetos

3.2.1 — Clase (molde)

Una clase es un plano, molde o plantilla que define los atributos (datos) y métodos (comportamientos) que tendrán los objetos creados a partir de ella.

public class Persona {
    // Atributos (datos)
    String nombre;
    int edad;

    // Método (comportamiento)
    void presentarse() {
        System.out.println("Hola, soy " + nombre + " y tengo " + edad + " años.");
    }
}

3.2.2 — Objeto (instancia)

Un objeto es una instancia concreta de una clase. Se crea con el operador new, que reserva memoria y llama al constructor.

Persona p1 = new Persona();  // p1 es un objeto de tipo Persona
p1.nombre = "Sonic";
p1.edad = 25;
p1.presentarse();             // "Hola, soy Sonic y tengo 25 años."

Persona p2 = new Persona();  // Otro objeto independiente
p2.nombre = "María";
p2.edad = 30;
p2.presentarse();             // "Hola, soy María y tengo 30 años."

3.2.3 — El operador punto

El punto (.) se usa para acceder a atributos y métodos de un objeto: objeto.atributo, objeto.metodo().

3.2.4 — NullPointerException

Ocurre cuando se intenta usar un objeto que no ha sido inicializado (vale null). Es una de las excepciones más comunes en Java.

Persona p = null;         // Declarada pero no inicializada
// p.nombre = "Sonic";    // ❌ NullPointerException
p = new Persona();         // Ahora sí: inicializada
p.nombre = "Sonic";        // ✅ OK
💡 Analogía: La clase es la receta de una pizza. El objeto es la pizza concreta que preparaste siguiendo la receta. Podés hacer muchas pizzas (objetos) con la misma receta (clase).

3.3 — Constructores

3.3.1 — ¿Qué es un constructor?

Es un método especial que se llama automáticamente al crear un objeto con new. Su propósito es inicializar los atributos del objeto en un estado válido.

  • Tiene el mismo nombre que la clase.
  • No tiene tipo de retorno (ni siquiera void).
  • Se llama una sola vez, al momento de la creación.

3.3.2 — Constructor por defecto

Si no se define ningún constructor, Java provee uno vacío sin parámetros que inicializa los atributos a sus valores por defecto (0, null, false).

3.3.3 — Constructor personalizado

public class Persona {
    String nombre;
    int edad;

    // Constructor personalizado
    public Persona(String nombre, int edad) {
        this.nombre = nombre;  // this.nombre = atributo, nombre = parámetro
        this.edad = edad;
    }
}

// Uso
Persona p = new Persona("Sonic", 25);  // Llama al constructor

3.3.4 — La palabra clave this

this es una referencia al objeto actual. Se usa para:

  • Desambiguar atributos de parámetros con el mismo nombre: this.nombre = nombre;
  • Llamar a otro constructor de la misma clase: this(otroParametro); (debe ser la primera línea).
  • Pasar el objeto actual como argumento a otro método: otroObjeto.metodo(this);

3.3.5 — Sobrecarga de constructores

Se pueden definir múltiples constructores con diferentes listas de parámetros. Java elige cuál llamar según los argumentos proporcionados.

public class Persona {
    String nombre;
    int edad;

    // Constructor completo
    public Persona(String nombre, int edad) {
        this.nombre = nombre;
        this.edad = edad;
    }

    // Constructor con solo nombre (edad por defecto)
    public Persona(String nombre) {
        this(nombre, 0);  // Llama al constructor completo
    }

    // Constructor vacío (valores por defecto)
    public Persona() {
        this("Sin nombre", 0);
    }
}

3.4 — Encapsulamiento

3.4.1 — Modificadores de acceso

ModificadorVisible enUso típico
privateSolo la misma claseAtributos que no deben modificarse desde fuera
publicTodas las clasesMétodos que forman la interfaz pública
protectedMisma clase, subclases y mismo paqueteAtributos heredables pero no públicos
(default)Solo el mismo paqueteClases y métodos internos del paquete

3.4.2 — Getters y Setters

Los atributos se declaran private y se accede a ellos mediante métodos públicos getXxx() y setXxx(valor). Esto permite validar datos y cambiar la implementación interna sin afectar el código externo.

public class CuentaBancaria {
    private double saldo;  // Atributo privado

    // Getter: permite leer (no modificar)
    public double getSaldo() {
        return saldo;
    }

    // Setter: permite modificar con validación
    public void setSaldo(double nuevoSaldo) {
        if (nuevoSaldo >= 0) {
            this.saldo = nuevoSaldo;
        } else {
            System.out.println("El saldo no puede ser negativo.");
        }
    }
}

3.4.3 — Ventajas del encapsulamiento

  • Protección de datos: los setters pueden validar valores antes de asignarlos.
  • Mantenibilidad: se puede cambiar la implementación interna sin romper el código que usa la clase.
  • Control de acceso: se pueden crear atributos de solo lectura (getter sin setter).
  • Ocultamiento: el usuario de la clase no necesita saber cómo funciona internamente.
💡 Principio fundamental: Los atributos siempre private. Los métodos que forman la API pública, public. Solo exponé lo que el mundo exterior realmente necesita saber.

3.5 — Herencia

3.5.1 — extends

La herencia permite crear una clase nueva (subclase o clase hija) basada en una clase existente (superclase o clase padre). La subclase hereda atributos y métodos y puede agregar o modificar comportamiento.

// Superclase
public class Animal {
    protected String nombre;

    public Animal(String nombre) {
        this.nombre = nombre;
    }

    public void comer() {
        System.out.println(nombre + " está comiendo.");
    }
}

// Subclase
public class Perro extends Animal {
    public Perro(String nombre) {
        super(nombre);  // Llama al constructor de Animal
    }

    public void ladrar() {
        System.out.println(nombre + " dice: ¡Guau!");
    }
}

3.5.2 — super()

super() llama al constructor de la clase padre. Debe ser la primera instrucción del constructor de la subclase. Si no se escribe explícitamente, Java inserta super() (sin argumentos) automáticamente. super.metodo() permite llamar a un método de la clase padre desde la subclase, incluso si fue sobrescrito.

3.5.3 — Herencia simple

Java solo permite herencia simple: una clase puede extender una sola superclase. Esto evita la ambigüedad del "problema del diamante" presente en lenguajes con herencia múltiple como C++. La herencia múltiple de comportamiento se logra mediante interfaces.

3.5.4 — Jerarquía de clases

Todas las clases en Java heredan directa o indirectamente de Object. Esto significa que toda clase tiene métodos como toString(), equals() y hashCode().

3.5.5 — "ES UN" vs "TIENE UN"

  • "ES UN" (herencia): Perro extends Animal — un Perro ES UN Animal.
  • "TIENE UN" (composición): Coche tiene Motor — se modela con un atributo, no con herencia.

Usar herencia solo cuando hay una relación "ES UN" genuina. Para relaciones "TIENE UN", usar composición.

ErrorDescripción
Falta super()Si la superclase no tiene constructor vacío, la subclase debe llamar explícitamente a super(args)
Herencia múltipleclass A extends B, C — error de compilación en Java
Abusar de la herenciaUsar herencia para "reutilizar código" en vez de para modelar jerarquías reales

3.6 — Polimorfismo

3.6.1 — @Override

Sobrescribir un método significa redefinir en la subclase un método heredado de la superclase, manteniendo la misma firma (nombre, parámetros y tipo de retorno). La anotación @Override es opcional pero recomendada: el compilador verifica que realmente se está sobrescribiendo un método existente.

public class Animal {
    public void hacerSonido() {
        System.out.println("El animal hace un sonido.");
    }
}

public class Perro extends Animal {
    @Override
    public void hacerSonido() {
        System.out.println("El perro ladra: ¡Guau!");
    }
}

public class Gato extends Animal {
    @Override
    public void hacerSonido() {
        System.out.println("El gato maúlla: ¡Miau!");
    }
}

3.6.2 — Upcasting

Es tratar un objeto de una subclase como si fuera de la superclase. Es seguro y no requiere cast explícito porque un Perro siempre ES UN Animal.

Animal a = new Perro("Firulais");  // Upcasting implícito
a.comer();                           // Método de Animal
// a.ladrar();                       // ❌ Error: el compilador ve a como Animal

3.6.3 — Dynamic dispatch (enlace dinámico)

Cuando se llama a un método sobrescrito a través de una referencia de la superclase, Java ejecuta la versión de la subclase (el tipo real del objeto en tiempo de ejecución), no la de la superclase.

Animal[] mascotas = {new Perro("Firulais"), new Gato("Mishi")};
for (Animal a : mascotas) {
    a.hacerSonido();  // Dynamic dispatch: cada objeto usa su propia versión
}
// Imprime:
// "El perro ladra: ¡Guau!"
// "El gato maúlla: ¡Miau!"

3.6.4 — Override vs Overload (sobrescribir vs sobrecargar)

CriterioOverrideOverload
¿Dónde?Entre superclase y subclaseEn la misma clase
FirmaIdéntica (mismo nombre, mismos parámetros)Distinta (diferentes parámetros)
Anotación@OverrideNo tiene anotación especial
ResoluciónEn tiempo de ejecución (dynamic dispatch)En tiempo de compilación

3.7 — Clases Abstractas e Interfaces

3.7.1 — Clase abstracta (abstract class)

Una clase que no puede instanciarse directamente. Puede contener métodos abstractos (sin cuerpo, solo la firma) y métodos concretos (con implementación). Las subclases concretas están obligadas a implementar todos los métodos abstractos.

public abstract class Figura {
    protected String color;

    public Figura(String color) {
        this.color = color;
    }

    // Método abstracto: las subclases DEBEN implementarlo
    public abstract double calcularArea();

    // Método concreto: las subclases lo heredan tal cual
    public void mostrarColor() {
        System.out.println("Color: " + color);
    }
}

public class Circulo extends Figura {
    private double radio;

    public Circulo(String color, double radio) {
        super(color);
        this.radio = radio;
    }

    @Override
    public double calcularArea() {
        return Math.PI * radio * radio;
    }
}

3.7.2 — Interface

Una interfaz es un "contrato" que define qué métodos debe implementar una clase, sin especificar cómo. Una clase puede implementar múltiples interfaces (herencia múltiple de tipo).

public interface Volador {
    void volar();       // Método abstracto implícito (public abstract)
    void aterrizar();
}

public interface Nadador {
    void nadar();
}

// Una clase puede implementar múltiples interfaces
public class Pato implements Volador, Nadador {
    @Override
    public void volar() {
        System.out.println("El pato vuela.");
    }
    @Override
    public void aterrizar() {
        System.out.println("El pato aterriza.");
    }
    @Override
    public void nadar() {
        System.out.println("El pato nada.");
    }
}

3.7.3 — Default methods (Java 8+)

Desde Java 8, las interfaces pueden tener métodos con implementación por defecto usando la palabra clave default. Esto permite agregar nuevos métodos a interfaces existentes sin romper las clases que las implementan.

3.8 — ArrayList

3.8.1 — ¿Por qué ArrayList?

A diferencia de los arrays, ArrayList tiene tamaño dinámico: crece y se reduce automáticamente según se agregan o eliminan elementos. Pertenece al paquete java.util y usa genéricos para garantizar seguridad de tipos.

3.8.2 — Declaración y uso básico

import java.util.ArrayList;

ArrayList nombres = new ArrayList<>();  // <> operador diamante

// Agregar elementos
nombres.add("Ana");
nombres.add("Luis");
nombres.add("Carlos");

// Acceder por índice
System.out.println(nombres.get(0));  // "Ana"

// Tamaño
System.out.println(nombres.size());  // 3

// Eliminar
nombres.remove("Luis");              // Elimina por objeto
nombres.remove(0);                   // Elimina por índice

// Verificar existencia
if (nombres.contains("Ana")) {
    System.out.println("Ana está en la lista");
}

3.8.5 — Autoboxing y genéricos

Los genéricos no aceptan tipos primitivos: ArrayList<int> no compila. Se deben usar las clases wrapper: ArrayList<Integer>. Java convierte automáticamente entre int e Integer (autoboxing/unboxing).

ArrayList numeros = new ArrayList<>();
numeros.add(10);       // Autoboxing: int → Integer
numeros.add(20);
int suma = numeros.get(0) + numeros.get(1);  // Unboxing: Integer → int
System.out.println(suma);  // 30

4.2 — Manejo de archivos (File I/O)

4.2.1 — Lectura de archivos

Java provee varias formas de leer archivos. La más simple para archivos de texto es combinar FileReader con BufferedReader. La construcción try-with-resources cierra automáticamente el recurso al finalizar.

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class Lector {
    public static void main(String[] args) {
        String ruta = "datos.txt";
        try (BufferedReader br = new BufferedReader(new FileReader(ruta))) {
            String linea;
            while ((linea = br.readLine()) != null) {
                System.out.println(linea);
            }
        } catch (IOException e) {
            System.out.println("Error al leer: " + e.getMessage());
        }
    }
}

4.2.2 — Escritura de archivos

import java.io.BufferedWriter;
import java.io.FileWriter;
import java.io.IOException;

try (BufferedWriter bw = new BufferedWriter(new FileWriter("salida.txt"))) {
    bw.write("Primera línea");
    bw.newLine();
    bw.write("Segunda línea");
} catch (IOException e) {
    System.out.println("Error al escribir: " + e.getMessage());
}

4.2.3 — Try-with-resources

Introducido en Java 7. Los recursos declarados entre paréntesis del try se cierran automáticamente al finalizar el bloque, sin necesidad de un bloque finally. Solo funciona con clases que implementan AutoCloseable.

4.2.4 — Parseo de CSV con split()

String linea = "Juan,25,Argentina";
String[] partes = linea.split(",");
String nombre = partes[0];   // "Juan"
int edad = Integer.parseInt(partes[1]);  // 25
String pais = partes[2];     // "Argentina"

4.3 — Excepciones

4.3.1 — try-catch-finally

El manejo de excepciones permite que el programa reaccione ante errores en tiempo de ejecución sin detenerse abruptamente.

try {
    int resultado = 10 / 0;          // ArithmeticException
    int[] arr = new int[3];
    arr[5] = 99;                     // ArrayIndexOutOfBoundsException
} catch (ArithmeticException e) {
    System.out.println("Error aritmético: " + e.getMessage());
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Índice fuera de rango");
} catch (Exception e) {
    System.out.println("Error general: " + e.getMessage());
} finally {
    System.out.println("Esto se ejecuta siempre (haya o no error).");
}

UncheckedHeredan de RuntimeExceptionNo obligan a capturarlasNullPointerException, ArithmeticException

4.4 — Excepciones propias

4.4.1 — Crear una excepción personalizada

Para representar errores específicos del dominio de la aplicación se pueden crear excepciones propias extendiendo Exception (checked) o RuntimeException (unchecked).

// Excepción checked (obliga a capturar)
public class SaldoInsuficienteException extends Exception {
    public SaldoInsuficienteException(String mensaje) {
        super(mensaje);
    }
}

// Excepción unchecked (no obliga a capturar)
public class EdadInvalidaException extends RuntimeException {
    public EdadInvalidaException(String mensaje) {
        super(mensaje);
    }
}

4.4.2 — throw y throws

  • throw: lanza una excepción en un punto específico del código.
  • throws: declara que un método puede lanzar una excepción (checked), delegando la responsabilidad de capturarla a quien lo llame.
public class Cuenta {
    private double saldo;

    public void retirar(double monto) throws SaldoInsuficienteException {
        if (monto > saldo) {
            throw new SaldoInsuficienteException(
                "Saldo insuficiente. Disponible: $" + saldo);
        }
        saldo -= monto;
    }
}

4.5 — JVM, Bytecode y compilación

4.5.1 — El flujo de compilación

Java sigue un proceso de dos pasos: compilación y ejecución.

  1. Código fuente (.java) → compilador javac → bytecode (.class)
  2. Bytecode (.class) → JVM (java) → código máquina (en tiempo de ejecución)
# Compilar
javac MiPrograma.java          # Genera MiPrograma.class

# Ejecutar
java MiPrograma                # La JVM ejecuta el bytecode

4.5.2 — ¿Qué es la JVM?

La Java Virtual Machine es una máquina virtual que ejecuta bytecode. Es la responsable del lema "Write Once, Run Anywhere": el mismo .class puede ejecutarse en cualquier sistema operativo que tenga una JVM instalada. La JVM provee además manejo automático de memoria (Garbage Collector) y seguridad (sandbox).

4.5.3 — Compilación multi-archivo

# Compilar todos los .java de un directorio
javac *.java

# Compilar especificando destino de .class
javac -d bin/ src/com/miapp/*.java
💡 Dato: El bytecode es un lenguaje intermedio independiente de la plataforma. No es código máquina nativo, sino instrucciones que la JVM interpreta o compila "just-in-time" (JIT) a código nativo.

4.6 — Exportación JAR

4.6.1 — ¿Qué es un JAR?

Un archivo JAR (Java ARchive) es un paquete comprimido (formato ZIP) que contiene archivos .class, recursos y metadatos. Permite distribuir una aplicación Java como un solo archivo.

4.6.2 — Crear un JAR ejecutable

# 1. Crear MANIFEST.MF con la clase principal
# Contenido del archivo MANIFEST.MF:
# Main-Class: com.miapp.Principal
#
# 2. Empaquetar
jar cfm MiApp.jar MANIFEST.MF -C bin/ .

# 3. Ejecutar
java -jar MiApp.jar

5.1 — Git: Fundamentos

5.1.1 — ¿Qué es Git?

Git es un sistema de control de versiones distribuido. Permite registrar el historial de cambios de un proyecto, volver a versiones anteriores, trabajar en paralelo con ramas y colaborar con otros desarrolladores. Fue creado por Linus Torvalds en 2005.

5.1.2 — Los tres estados de Git

Git maneja tres áreas donde los archivos pueden residir:

ÁreaDescripciónComando
Working DirectoryLos archivos en tu disco, donde trabajás—
Staging AreaArchivos marcados para el próximo commitgit add
Repository (.git)Historial de commits almacenado localmentegit commit

5.1.3 — Flujo de trabajo básico

  1. Modificar archivos en el Working Directory.
  2. Agregar los cambios al Staging Area con git add.
  3. Confirmar los cambios al repositorio con git commit.
💡 Diferencia clave: Git es distribuido: cada desarrollador tiene una copia completa del historial en su máquina. No depende de un servidor central para funcionar (a diferencia de SVN).

5.2 — Comandos esenciales de Git

5.2.1 — git init

Inicializa un nuevo repositorio Git en el directorio actual. Crea una carpeta oculta .git que contiene toda la base de datos del historial.

git init                    # Crea repositorio en el directorio actual
git init nombre-proyecto    # Crea directorio y repositorio dentro

5.2.2 — git status

Muestra el estado actual: archivos modificados, en staging, sin seguimiento. Es el comando más usado para entender qué está pasando.

git status

5.2.3 — git add

Agrega archivos al Staging Area, preparándolos para el próximo commit.

git add archivo.java        # Agrega un archivo específico
git add *.java               # Agrega todos los .java
git add .                    # Agrega todos los cambios del directorio actual

5.2.4 — git commit

Guarda los cambios del Staging Area en el repositorio como una nueva versión (commit). Cada commit tiene un mensaje descriptivo y un identificador único (hash SHA-1).

git commit -m "Agrega clase Persona con getters y setters"
git commit -m "Corrige bug en cálculo de saldo"

5.2.5 — git log

Muestra el historial de commits en orden cronológico inverso.

git log                     # Historial completo
git log --oneline           # Una línea por commit (resumido)
git log --oneline -5        # Últimos 5 commits

5.2.6 — git checkout

Permite moverse entre commits o ramas, o restaurar archivos a un estado anterior.

git checkout nombre-rama     # Cambia a una rama
git checkout -- archivo.java # Descarta cambios locales (restaura)

5.2.7 — .gitignore

Archivo que indica a Git qué archivos o directorios debe ignorar (no versionar). Esencial para excluir archivos compilados, dependencias, configuraciones locales e información sensible.

# Ejemplo de .gitignore para proyectos Java
*.class
*.jar
bin/
target/
.idea/
*.iml
.settings/
.classpath
.project

5.3 — Git remoto y GitHub

5.3.1 — Repositorios remotos

Un repositorio remoto es una copia del proyecto alojada en un servidor (GitHub, GitLab, Bitbucket). Permite compartir código y colaborar con otros desarrolladores.

5.3.2 — git remote add

Vincula el repositorio local con un repositorio remoto.

git remote add origin https://github.com/usuario/repositorio.git

5.3.3 — git push

Envía los commits locales al repositorio remoto.

git push -u origin main      # Primer push: establece upstream
git push                     # Pushs subsiguientes (ya configurado)

5.3.4 — git pull

Trae los cambios del repositorio remoto y los fusiona con la rama local.

git pull origin main         # Descarga y fusiona cambios remotos

5.3.5 — Flujo de trabajo con remotos

  1. git pull para traer los últimos cambios.
  2. Trabajar localmente: modificar, add, commit.
  3. git push para subir los cambios.

Este flujo pull-commit-push es el día a día del desarrollo colaborativo con Git.

5.4 — IDEs para Java

5.4.1 — Eclipse IDE

Uno de los IDEs más veteranos para Java. Gratuito y de código abierto. Destaca por su ecosistema de plugins, su perspective-based UI y su potente soporte para refactoring. Integración Git integrada (EGit).

5.4.2 — IntelliJ IDEA

Considerado por muchos el IDE más inteligente para Java. Ofrece autocompletado contextual avanzado, análisis estático profundo y navegación de código superior. La versión Community es gratuita; la Ultimate es de pago. Integración Git nativa excepcional.

5.4.3 — VS Code

Editor ligero y altamente extensible. Con el paquete de extensiones "Extension Pack for Java" se convierte en un entorno Java funcional. Ideal para proyectos pequeños o para quien prefiere un editor rápido sobre un IDE pesado. Soporte Git integrado en la interfaz.
